# 주형 담당 후속 작업, 현업 촬영 recipe와 재촬영 검사 시연

현재 restoration-anomaly-benchmark에서 실제 작업한다. 목표는 기존 SR/PatchCore 정량 근거와 스마트폰 기반 실물 입력을 연결하고, 고정 촬영·복원·조건부 재촬영·고정 다중 조명의 효과와 비용을 비교할 수 있는 작은 검사 스테이션을 완성하는 것이다. 구현·분석·포스터 원고를 병행한다.

설계에는 사용자가 요청한 5.2 설정을 사용하고 실제 선택된 모델명을 기록한다. 이전 Opus/Fable 초안의 존재와 읽은 문맥을 명시한다. 이미 완료한 초안을 다시 독립 설계로 만들거나 같은 실험을 반복할 필요는 없다. 세부 구현 판단은 맡은 source에서 자율적으로 하되 첫 test 비교 전에 선택 근거와 평가 기준을 기록한다.

## 시작점

현재 root·HEAD·작업 트리·worker와 최근 본인 PROGRESS를 확인한다. 사용자 변경과 진행 중 작업을 보존한다. 전달 branch는 문서 수신용이며 기존 phone 구현 checkout을 유지한다. 현재 phone 실행 source 기준은 exp/phone-lighting-juhyung의 aa2f7fa다. 더 최신 본인 코드가 있으면 차이를 확인하고 실제 source를 기록한다.

git show origin/handoff/juhyung:docs/INDUSTRIAL_CAPTURE_COMPARISON_20261113.md
git show origin/handoff/juhyung:docs/PROMPT_JUHYUNG_INDUSTRIAL_CAPTURE_20261113.md

읽을 범위는 위 비교군 문서, 현재 phone 품질 프로토콜·가이드와 phone_* 코드, 기존 InspectionStation 계약, 본인의 최신 결과다. CPU가 확인한 제조사 자료는 재검색을 반복하지 말고 설계에 영향을 주는 미해결 항목만 보완한다. 기존 image-score/noise/clean-control/9사례 분석은 완료 상태로 재사용한다.

## 확보된 입력과 일정

사용자는 그래픽카드 뒷면을 주 대상으로 선택했다. 실제 예시 사진 6장은 회전·원근·배율·부분 FOV 변화가 섞여 있고 조명 조건과 반복 라벨은 미확인이다. CPU가 local-only로 보관했다. 사진은 Git에 없다. 실제 파일을 받기 전에는 supplied_input_available=false로 기록하고 synthetic 구현을 진행한다.

첫 그래픽카드 한 장의 별도 개발 audit에서, 수치 확인 전에 정한 ROI(.10,.25,.40,.70), working long side1024 기준 clipped-high1.05191%, clipped-low0.0234592%, meanY113.3454가 관측됐다. 기존1% high-clipping 규칙이 RETAKE를 냈다. 이 값은 정상 조명 ground truth나 결함 판정이 아니다. 단일 자기 기준 등록의 정렬오차0을 영상간 정렬 성능으로 쓰지 않는다. 기존 어댑터의 검은 재질 clipped-low 문제도 함께 고려한다.

통제 촬영 계획은 같은 물체·카메라·배경에서 조명3조건×3회9장, 초점 흐림3장, 같은 모사 표면 이물의 기준/측면 조명 각3장으로 총18장이다. 기본12장부터 입력할 수 있다. 새 사진 한 장으로 intake와 표시부터 연결하며 전체 촬영 완료를 모든 작업의 선행조건으로 두지 않는다.

제출 마감은2026-12-01화요일23:59의 A0 PDF다. 실제 발표일은 미확인이다. 내부 목표는11월23일 핵심 실험 정리,27일 포스터 초안,29일 최종 점검이다. A0 원본 양식은 CPU에 있으며 세로 약841×1189mm,우측상단 팀번호 유지,9개 예시 중3번 구성이 권장된다. 원본 파일 수신 전에도 편집 가능한 본문·그림 배치를 진행한다.

## 작업 1. 현업 대응 설계를 짧게 확정한다

CPU 보고서를 검토해 현장 조건을 한 페이지로 대응시킨다. 현재 구현 대상은 정지 촬영형 수동 입력 스테이션이다. 품목/recipe 선택,위치 맞춤,정해진 FOV 촬영,입력 품질,검사 또는 REVIEW,재촬영,이력 저장을 연결한다.

실제 PLC·strobe·encoder·3D 계측과의 차이는 구현 상태로 명시한다. 공장별 허용 미검·takt가 미확인인 동안 공통 합격 숫자를 만들지 않는다. 보유 카메라·조명·기판과 추가구매0원 범위를 유지한다. 설계 문서 전체의 완성을 이후 구현의 선행조건으로 삼지 않는다.

## 작업 2. recipe·등록·관찰 영역을 실제 코드로 연결한다

기존 phone_* 모듈과 입력표를 재사용한다. Recipe에는 part/view,anchor,FOV/관찰ROI,카메라모드,조명,계산용크기와 보간,허용되는 입력 조건,선택된 정책버전을 기록한다. 미확인 camera/조명 항목은 unknown이다.

서로 다른 회전·배율·부분 시야를 정상 조명 변화와 구분한다. 관찰 ROI의 projected coverage와 정렬 신뢰도를 확인한다. 화면 밖으로 사라진 부위를 보정 완료로 처리하지 않는다. 품질은 기존 원칙대로 정렬 보간 전 화소에서 계산하고 native/working 측정 단위를 구분한다. 배경에만 잘 맞는 정렬을 잡도록 부품 모서리·관찰 부위의 검증을 추가한다. 미확인mm/lux는미측정으로 남긴다.

Synthetic 변환으로 정상·회전·배율·원근·관찰부위 잘림·정렬실패를 테스트한다. 실제 이미지가 없으면 코드·예제·테스트까지 완료한다.

## 작업 3. 기존 품질 정책과 단일 개선안을 비교한다

v0.1 고정 clipping/선명도 규칙을 기준 ablation으로 보존한다. 검은 재질,원래 밝은 납땜/흰 인쇄,새 반사,관찰 부위 소실을 구분할 개선안 하나를 본인이 선택한다. 정상 참조 대비 변화와 task ROI 유효성을 우선 검토하되 임의로 복잡한 모델을 추가하지 않는다.

짧은 DESIGN_DECISION.md에 후보·선택 이유·수식·단위·normal-only calibration·fallback·실패 조건을 적고 첫 평가 전에 버전과 기준을 고정한다. 입력이3장뿐이면 calibration의 근거와 한계를 그대로 기록한다. test 이물/판정 결과로 기준을 재선택하지 않는다. 개발 입력을 사용한 수정과 후속 고정 평가 세션을 분리한다.

숫자를 통과시키는 것보다 판독 가능한 입력의 과도한 거부와 판독 어려운 입력의 통과를 함께 계산한다. 사람의 판독 가능 기록은 알고리즘 출력과 별개로 수집한다. 이 지표는 실물 결함 미검률과 구분한다.

## 작업 4. 작은 golden-reference 검사와 bounded retake를 연결한다

실제 결함 탐지기를 연결할 때까지 station은 REVIEW를 유지한다. 우선 정렬 후 기준 사진과의 차이를 보는 작은 검사 baseline을 구현·테스트한다. 정상 참조로 기준을 정하고 모사 이물은 surface_foreign_object_simulation으로 표시한다. 실제 전기적 고장이나 단선 라벨을 만들지 않는다.

기존 InspectionStation을 사용해 동일 cycle의 첫 촬영,품질 알림,사전 지정 대체 조명 재촬영,최종검토를 연결한다. 최대 추가촬영은1회,총2장으로 고정한다. 두 번째도 미해결이면REVIEW 또는ERROR로 남긴다. 요청 중복·stale결과·누락·timeout은 기존 계약을 재사용한다. 새 웹 앱 대신 기존 HTML에 원본/관찰부위/알림/재촬영이력을 보이게 한다.

정상 참조와 한 개의 모사 이물만으로 일반 산업 결함검출을 입증했다고 쓰지 않는다. 실제 파일이 오면 기존 intake와 source hash를 기록하고 가능한 입력부터 실행한다.

## 작업 5. 비교 실행기를 작은 단위로 완성한다

C0고정촬영+직접검사,C1같은입력+고정복원+동일검사,C2품질정책+조건부재촬영,C3항상두고정조명촬영의 비교를 지원한다. C2는v0.1과새단일정책을 별도ablation으로 둔다. C0/C1은같은1장,C2/C3는같은최초입력과같은두번째조명으로최대2장예산을맞춘다. C3의조명별참조/판정결합규칙을사전에고정한다.

C1은기존checkpoint/복원adapter를재사용한다. 실물입력의degradation유무·해상도·입출력좌표·타일과runtime범위를명시한다. 기존benchmark의×4조건과다른실물처리면별도family로기록한다. 실제clean정답이없는다른조명사진을SR PSNR/SSIM의정답으로대입하지않는다. 모델이나입력이없으면해당조건만pending으로두고나머지코드와synthetic연결을완료한다.

먼저fake카메라/검사/복원으로end-to-end를검증하고실제입력이오면고정된범위로실행한다. 모든최초cycle의최종상태·촬영수·해결/미해결·review부하를남기고PASS만남겨분모를줄이지않는다. 원본·재촬영·recipe·source·policy·결과출처를연결한다. 같은사진의새처리를새독립부품으로집계하지않는다.

기존MVTec/VisA의primary pooled AU-PRO와frozen정의는유지한다. 실물라벨이있는경우만확인된NG중최종OK비율,정상중최종NG비율,정상중NG/REVIEW비율을분모와함께보고한다. GT없는경우NA와unknown수를기록한다. software처리시간과실제수동촬영시간을분리하고물리cycle미측정이면장비throughput을만들지않는다.

## 작업 6. 시연·포스터 원고를 함께 만든다

원본/고정ROI/차이또는알림map/판정근거/재촬영전후/이력을연결한기존HTML시연과재현CLI를완성한다. 실제입력과synthetic시연을화면에서구분한다. 실제결과가확보된패널부터그림·캡션·주장–근거표로묶는다.

포스터는기존SR/PatchCore정량결과를중심으로하고실물촬영정책의효과·비용을별도패널로둔다. 모바일/브라우저검증은변경된부분에집중한다. 과거390CSSviewport정정과완료검증을재사용한다.

보유UNO와USB케이블이확인되면내장LED로READY/재촬영/REVIEW상태를표시하는작은추가시연을검토할수있다. 기존fake-controller와같은상태계약을사용하고실제장치연결전에는simulation으로표시한다. 새부품구매·실제부품배출동작은범위밖이다. 이추가시연이기본실험·포스터를지연시키면문서초안까지만남긴다.

## 병행·종료·반환

기준이고정된기존승인실험과위구현을병행한다. 지혁의bank-domain producer는지혁소유,CPU는분석/통합소유다. 같은파일을동시에재작성하지않고필요한shared-interface변경만협의한다. 신규모델/category대량탐색·bank/seed/geometry변경·기존결과재실행은이번queue에추가하지않는다.

관련테스트→필요한회귀테스트/CPU smoke→diff검사를실행한다. source변경이있으면가능한전체pytest를수행하고미완료범위를정확히적는다. 변경없는전체suite를완료단위마다반복할필요는없다. Source코드·테스트·공개문서는본인실행branch,반환metadata/receipt는handoff/juhyung의기존계약을따른다. 공개경로는상대경로,원본SHA와공개사본연결을남긴다.

완료단위마다PROGRESS에실제수행·결과·파일·commit·실패·다음작업을기록한다. ignored/untracked RESEARCH_EVOLUTION_LOCAL.md에는검증가능한대안·근거·선택·수정·남은질문을결정ID/run/commit과연결해기록한다. 내부사고과정은기록하지않는다. Private노트는원문또는증분을SHA256과함께별도비공개로반환한다. 공개진행사본만으로private결정기록이전달됐다고간주하지않는다.

원본사진/RGB/GT/rawarray/bank/dataset/weights/private노트는Git대상에서제외한다. 원격실행·장치측정·실물결함성능은실제수행한범위만기록한다. 새입력이없는동안에는위코드·테스트·원고·시연준비까지완료하고완료된queue에무한실험을붙이지않는다.
