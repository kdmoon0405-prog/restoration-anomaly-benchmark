# Claude Fable 5.2 최종 구현·시연·보고서·포스터 일괄 실행 지시

이 지시는 사용자가 요청한 후속 작업이다. 아래 범위의 설계 판단, 구현, 실행, 오류 수정, 결과 분석, 자체 검토와 최종 파일 제작을 모두 맡는다. 계획이나 원고 초안에서 멈추지 말고 지금 받은 입력으로 완성할 수 있는 결과물을 끝까지 만든다. 중간 단계마다 계속할지 확인받을 필요는 없다. 새 실제 사진·사람 판독·실물 하드웨어가 필요한 항목은 한 번에 정리하고 다른 작업을 병행한다.

## 1. 최종 결과물

생산라인의 고정 촬영 recipe와 검사 흐름을 고려한 스마트폰 기반 PCB 외관검사 시제품을 완성한다. 현재 주 대상은 사용자가 촬영한 그래픽카드 뒷면이다. 사용자는 이 결과물과 보고서를 받아 실제 동작·비교 결과·설계의 타당성을 판단한다.

사용자가 기존 실행 진입점에서 입력 폴더와 촬영 기록을 지정하면 part/session/recipe 확인, 정렬과 관찰 ROI 확인, 입력 품질 판단, 조명별 golden-reference 검사, 필요한 경우 최대 1회 대체 조명 입력, 최종 OK/NG/REVIEW와 이유, HTML/CSV 이력 저장까지 이어져야 한다. 사진·ROI·차이 지도·검사 점수·품질 상태·추가 입력 이력을 같은 cycle에서 확인할 수 있게 한다. 시연용 실행 명령과 대표 사례를 함께 제공한다.

기존 SR/PatchCore 정량 연구는 복원의 효과와 실패 조건을 설명하는 근거로 사용한다. 실물 촬영 실험의 성립 범위와 개발 순서도 보고서에 포함한다. 현업 대응 설계, 사용할 방법과 비교군, 구현 상태, 실측 결과와 남은 외부 입력을 최종 보고서 한곳에서 확인할 수 있게 한다.

최종 파일은 실행 코드, 실행 가능한 시연, 결과 보고서, 자체 검토 보고서, 실제 그림을 배치한 편집형 A0 PPTX와 PDF다. 사용자가 파일을 열어 판단할 수 있는 상태까지 완성한다.

## 4. 설계를 마무리하고 정상 실행 경로를 완성한다

기존 한 페이지 현업 대응 설계와 v0.2 문서를 읽고 최종 방법, 비교군, 입출력, 상태 전이, 실패 시 동작, 관찰 가능한 범위를 확정한다. 이미 고정되어 실행 가능한 구현과 포스터 제작을 함께 진행한다.

기존 phone_* 모듈·InspectionStation·recipe·CSV/HTML·consumer를 재사용한다. 폴더 입력부터 최종 보고서 저장까지 일반 사용 경로에서 실제로 동작하도록 연결한다. 정렬 실패·관찰 ROI 소실·잘못된 recipe·누락 파일·대체 입력 미도착도 최종 상태와 이유를 남긴다. 재실행 때 원본 입력과 기존 완료 결과를 덮어쓰지 않게 한다.

누락된 synthetic 원근 변환 시험을 추가한다. 회전·배율·이동·부분 시야·정렬 실패와 함께 현재 정렬 방식의 허용·거절 범위를 확인한다. 원근 입력에서 처리 가능한 범위와 REVIEW/RETAKE로 보내는 범위를 구체적으로 적는다. 배경에만 맞는 정합과 실제 관찰 ROI의 정합을 확인한다. 새 지원 기능이 필요하면 기존 공통 경로에서 필요한 만큼 구현하고 해당 회귀 검사를 남긴다.

밝기제곱으로 나눈 선명도의 과보정은 최종 설계에서 다룬다. 현재 v0.2를 유지하면서 사용 범위를 설명할지, 개발 입력에서 근거 있는 수정안 하나를 만들지 직접 결정한다. 수정한다면 기존 v0.1/v0.2 결과를 보관하고 새 버전의 규칙·단위·기준·실패 조건을 첫 새 평가 전에 고정한다. 사람 판독 라벨 없이 어느 정책이 더 정확한지 순위를 만들지 않는다.

## 5. 비교 결과를 같은 사례와 단위로 정리한다

우선 대조군은 C0 고정 촬영·직접 검사와 C3 고정 두 조명 검사다. C2 조건부 추가 촬영과 C1 Bicubic/SwinIR을 같은 사례에 연결한다. 현업 대응 비교에서는 정상 입력의 NG, 모사 이물의 NG, 품질 보류, 추가 입력 부담과 실제 취득·처리 시간을 각각 제시한다.

기존 개발 결과를 정확히 반영한다.

- 전체16 cycle에서 C3는 두 번째 사진이 없는9 cycle이 NA다. 전체 분모를 보존한다.
- 두 조명 공통7 cycle의 C2v0.2/C3는 논리적 사진 사용10/14회다. 정상라벨 NG0/1건, 모사 이물 NG각3건이다.
- 참조·보정 사진을 대체로 재사용한 lowlight-1/2를 제외한 사후 진단5 cycle은6/10회다. normal-3와 lowlight-3는 같은 대체 사진을 공유한다.
- 공통7/5 cycle은 CPU 검토에서 만든 사후 진단이다. 한 보드·한 세션·같은 이물 위치의 반복과 사진 재사용을 기록한다.
- C1 Bicubic/SwinIR은16 cycle 모두 최종 판정이 같다. `phone_x4_roundtrip`은 작업 영상의0.25배 축소 후 x4 복원 조건이며 참조·보정에도 같은 처리를 적용했다.
- v0.2는 같은 개발 사진을 본 뒤 정했다. 사람 판독 기록과 물리 촬영 시간은 현재 미측정이다. 재촬영 비교는 미리 찍은 입력을 재생했다.

위 수치는 저장 CSV를 재사용한다. 이 결과에서 실제 라인 오탐률·미검률·처리량이나 SwinIR 고유 우위를 만들어 쓰지 않는다. 각 데이터의 단위와 출처를 최종 표·그림·화면에서도 표시한다.

## 6. 새 평가와 사람 판독까지 실행 준비를 끝낸다

새 촬영 세션의 작은 평가 계획과 실제 채울 수 있는 기록표를 완성한다. 기존 보드·스마트폰·두 조명을 사용하고 촬영량과 조건을 직접 정해 확정한다. 원래 모사 이물을 다른 위치에서도 관찰할 수 있는 작은 범위를 검토한다. 추가 구매는0원이다.

참조·정상 보정·평가용 사진은 각각 별도로 촬영하도록 한다. 같은 cycle의 첫 조명과 대체 조명은 같은 보드·같은 이물 상태를 유지하며, 사례별 대체 사진을 따로 받는다. 카메라·보드·ROI·조명 위치와 AE/AF·HDR·플래시의 실제 상태를 기록한다. 기준과 평가 입력 목록을 고정한 다음 비교를 실행한다. Threshold는 정상 참조·보정 자료에서 정하고 평가 이물 결과로 재선택하지 않는다.

사람 판독표에는 사진별 잘 보임/판독 어려움/불확실, 관찰 ROI, 실제 판독자와 기록 시점을 넣는다. 판독자는 알고리즘 결과를 보기 전에 표시하도록 안내한다. Fable 자체 사진 해석을 사람 판독 기록으로 채우지 않는다. 라벨이 확보되면 정책별 판독 어려운 입력의 통과, 판독 가능한 입력의 보류, 미해결 건수를 같은 분모에서 계산한다.

새 사진과 판독이 도착하면 이 고정 계획으로 비교·분석·그림·보고서를 갱신한다. 아직 도착하지 않았으면 필요한 최소 촬영·판독 요청을 하나로 모으고, 현재24장·synthetic·구현·보고서·포스터는 끝까지 완성한다. 미수신 결과 칸은 미측정으로 표시한다.

## 7. 시연과 UNO 연결을 끝까지 정리한다

대표 정상·모사 이물·저조도/흐림·자세/시야 실패를 실제 실행 화면에서 보여준다. 첫 입력, 품질 이유, 직접 검사, 조건부 대체 입력, 최종 상태와 이력을 따라갈 수 있게 한다. 기존 HTML에 들어 있는 실제 축소 사진과 차이 지도는 출처·cycle·조건을 연결해 시연에 사용한다.

UNO가 실제 연결되어 있으면 기존 제어 계약과 핀맵을 확인해 승인된 구성에서 상태 표시 시연을 수행한다. 사용할 실물이 없으면 기존 fake controller/serial 경로의 소프트웨어 E2E, 연결 가이드와 실행 예제까지 완성하고 실물 시험 상태를 적는다. 장치 유무가 다른 구현과 포스터 제작을 멈추는 조건이 되지 않게 한다.

시연용 실행 순서, 필요한 기존 파일, 재실행 방법, 오류 복구와 화면 캡처를 남긴다. 실제 시간은 촬영·준비·복원·검사·보고서 생성으로 구분해 측정 가능한 부분을 기록한다. software replay의 simulation_seconds와 물리 촬영 시간을 구별한다.

## 8. 그림과 공식 A0 포스터 파일을 완성한다

원고와 그림 후보 목록을 실제 배치된 PPTX/PDF로 완성한다. 공식 A0 원본은 별도 보관하고 작업 사본을 편집한다. 우측 상단 팀번호 영역과 양식 구조를 활용한다. 저자·소속·팀번호는 확인된 자료를 사용하고, 미확정 정보는 최종 보고서의 확인 항목에 모은다.

포스터에는 연구 질문과 최종 시스템 흐름, 기존 SR/PatchCore의 대표 정량 결과·실패 사례, 현재 실물 개발 사진의 관찰 범위, C0~C3의 같은 사례 비교, 결과의 한계를 넣는다. 기존 수치·선택 사례·계산 코드를 재사용하고 조건/family/분모/단위를 그림과 연결한다. 사진이 포함된 자료는 비공개 검토 산출물로 반환한다.

실제 사진·ROI 확대·차이 지도·상태 흐름과 정량 그림을 생성해 배치한다. 새 그림이 원자료와 일치하는지 확인하고 가독성·글자 크기·한글 폰트·표 잘림·그림 겹침을 렌더 결과에서 직접 검토한다. 편집 가능한 원본과 PDF, 그림 파일을 함께 반환한다. 원근 시험이나 새 평가 대기와 독립적으로 현재 근거의 완성된 검토본을 만든다.

## 9. 자체 검토와 오류 수정을 수행한다

구현·실험·포스터를 만든 뒤 원본 code/CSV/receipt와 렌더 파일을 다시 읽는 검토 단계를 수행한다. 실제 사용한 모델과 검토 방식을 기록한다. 같은 Fable의 자체 검토라는 점을 표시한다. 발견한 문제를 중요도·근거 파일·재현 방법과 함께 정리하고 수정 가능한 것은 바로 수정한 뒤 관련 검사를 다시 돌린다.

확인할 범위는 일반 진입점의 E2E, recipe/ROI/정렬 실패, 새 원근 합성 시험, 품질과 최종 검사 상태의 구분, 참조/보정/평가 분리, C3 NA와 사진 재사용, C1 조건 정의, 시간 단위, 그림의 원자료 일치, 실제 HTML 및 A0 PPTX/PDF 배치다. 전체 테스트와 CPU smoke는 현재 실행 source에 대해 필요한 검사를 마치고 명령·소요 시간·결과를 기록한다. 이미 유효한 동일 source의 완료 로그는 재사용한다.

기존 RAM/VRAM guard와 source 소유권을 유지하고 GPU 경합을 피한다. 지혁의 bank-domain24+4는 담당 producer에서 진행 중인 실행을 보존한다. 반환이 도착하면 source·split·calibration에 연결해 최종 근거에 통합한다. 기존 완료9사례·noise32·image-score200/160paired와 기존165조건 자료는 cache를 재사용한다.

실제 결과는 본인의 기존 공개 PROGRESS에 이어 쓰고 중앙에서 합칠 수 있게 반환한다. 선택·대안·수정·근거·남은 질문은 실제 ignored/untracked private 노트에 계속 기록한다. 공개 PROGRESS 사본과 실제 private 원문은 각각 전달한다.
