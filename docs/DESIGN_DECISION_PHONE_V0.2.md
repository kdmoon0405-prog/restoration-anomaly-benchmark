# DESIGN_DECISION — phone 품질 정책 v0.2, golden-reference 검사 v0.1, C0–C3 실행 규칙 (2026-11-15 고정)

- **작성 모델:** Claude Fable 5.2. 이전 Opus/Fable 초안과 CPU 비교군 문서를 읽은 상태다.
- **고정 시점:** 이 문서의 commit 이후에 아래 방법의 첫 실행을 한다. 그 뒤 수식·임계값·분할을 바꾸려면 새 버전으로 남긴다.
- v0.1(`PHONE_QUALITY_PROTOCOL_V0.1.md`)은 그대로 보존하고 ablation으로 쓴다.

## 0. 고정 전에 이미 본 것 (공개)

입력은 2026-11-15 세션 1개(그래픽카드 뒷면 1개, 24장)다. 이 문서를 쓰기 전에 다음을 봤다.

- 24장 전체의 v0.1 audit 수치(관찰 영역 = 화면 전체): 정렬 통계, 평균 밝기, clipping, 선명도, 반복 간 차이.
- 9장의 축소 사진(조건별 1장씩): L0의 포화가 책상 배경에서 난다는 것, F0/F1에 분홍 이물이 보인다는 것.
- anchor(L0 1번) 사진 전체.

보지 않은 것은 관찰 ROI 안의 수치, 기준 사진 차이 map, 어떤 검사 결과도다.

**따라서 이 세션의 결과는 전부 development 결과다.** 아래 "held-out"은 같은 세션 안에서 calibration에 쓰지 않은 반복이라는 뜻이고, 독립 평가 세션이 아니다. 고정 평가는 새 촬영 세션이 필요하다.

## 2. 정렬 검증 (v0.2 추가)

v0.1의 성공 조건(inlier ≥ 30, 비율 ≥ 0.25, 재투영 오차 중앙값 ≤ 1.5 px)에 다음을 더한다.

- **ROI inlier:** anchor 좌표에서 관찰 ROI 안에 있는 inlier ≥ 20개.
- **ROI inlier 분포:** 그 inlier들의 bounding box 넓이 ≥ ROI 넓이의 0.25.
- **투영 coverage:** ROI를 대상 사진으로 투영했을 때 사진 안에 들어오는 비율 ≥ 0.98.

앞의 둘은 배경에만 맞은 정렬을 걸러내고, 셋째는 관찰 부위가 화면 밖으로 나간 경우를 걸러낸다.

## 3. 품질 정책 v0.2 `ref_roi` (단일 개선안)

**후보와 선택**

| 후보 | 내용 | 판단 |
| --- | --- | --- |
| A. v0.1에 ROI만 적용 | 절대 clipping 1 % 규칙을 ROI 안에서 계산 | ablation으로 실행. 원래 밝은 납땜·흰 인쇄, 원래 검은 재질을 구분하지 못한다 |
| **B. 정상 참조 대비 변화 (`ref_roi`)** | ROI 안에서 참조에 없던 포화·암부만 센다. 선명도는 밝기로 정규화해 참조와 비교한다 | **선택.** 조원이 지적한 네 경우(검은 재질, 원래 밝은 부위, 새 반사, 관찰 부위 소실)를 한 규칙 체계로 나눈다. 추가 모델이 없다 |
| C. 학습 기반 품질 예측 | 판독 가능 여부를 분류기로 학습 | 기각. 라벨과 사진이 없다 |

**수식** (모두 계산용 픽셀, 코드값 0–255)

- `new_clip_high`: ROI에서, 대상은 포화(어느 채널이든 ≥ 250)인데 같은 위치의 참조는 포화가 아닌 화소의 비율. 참조의 포화 mask는 3×3으로 한 번 팽창시켜 1 px 정렬 오차를 허용한다. 대상의 mask는 warp 전 화소에서 만들고 최근접으로 옮긴다.
- `new_clip_low`: 같은 방식. 암부는 모든 채널 ≤ 5.
- `sharpness_norm`: Tenengrad ÷ (평균 Y/255)². 밝기가 달라도 흐림만 보려는 정규화다.
- `sharpness_ratio`: 대상의 `sharpness_norm` ÷ anchor의 `sharpness_norm`.

**판정**

| 상태 | 조건 |
| --- | --- |
| RETAKE | 파일 없음·읽기 실패 / 정렬 실패 또는 §2 검증 실패 / `new_clip_high` > 0.01 / `new_clip_low` > 0.01 |
| REVIEW | ROI 평균 Y < 40 / `sharpness_ratio` < 0.5 / 자세가 허용 범위 밖 / 중복 파일 / 해상도 불일치 |
| PASS | 그 외. 허용 범위 안의 자세 변화는 `pose_deviation`으로 기록만 한다 |

- **calibration:** 참조는 anchor 1장이다. 임계값 0.01, 40, 0.5는 v0.1에서 가져온 설계값이고 이 세션 자료로 맞추지 않았다. 자세 허용 범위 5°와 0.10은 v0.1 audit에서 기울임 세트가 약 14°, 다른 세트가 3–8 %인 것을 본 뒤 정한 값이다.
- **fallback:** 참조가 없거나 정렬이 실패하면 변화량을 계산할 수 없으므로 RETAKE다.
- **이 정책이 실패했다고 볼 조건:** 사람이 판독 가능하다고 기록한 사진을 거부하거나, 판독이 어렵다고 기록한 사진을 통과시키는 경우. 이번 세션에는 사람의 판독 기록이 없어(unknown) 이 비율은 NA다.

## 4. Golden-reference 검사 v0.1

탐지기가 아니라 "기준 사진과 달라진 곳"을 찾는 작은 baseline이다. 조명별로 참조를 따로 둔다.

1. 대상과 참조를 anchor 좌표로 옮긴다(bilinear). 둘 다 Gaussian σ = 1.5 px로 평활해 보간 차이를 줄인다.
2. 채널별 국소 정규화: N = (I − G₁₂∗I) ÷ (√(G₁₂∗(I − G₁₂∗I)²) + 2). G₁₂는 σ = 12 px Gaussian이다.
3. 차이 map: D = max over R,G,B of |N(대상) − N(참조)|, 그 뒤 σ = 2 px 평활.
4. 화소 임계값 τ = 2 × q0.999. q0.999는 정상 calibration 사진의 D에서 ROI(4 px 안쪽으로 줄인 영역) 화소로 구한다.
5. 점수: ROI 안에서 D > τ인 화소의 8-연결 덩어리 중 가장 큰 것의 넓이(px).
6. 판정: 점수 ≥ 25 px이면 NG, 아니면 OK.

**사전 수정 1 (2026-11-15, 실제 사진에 이 검사를 실행하기 전):** 처음 고정한 규칙(`e00eca6`)은 τ = q0.999, 판정 = 점수 > 2 × (calibration 사진의 점수)였다.
- 합성 입력 시험에서 정상 반복 10장 중 6장이 NG가 됐다(calibration 점수 53, 정상 점수 89–174). 사진 1장에서 구한 "가장 큰 덩어리 넓이"는 극값 통계라 흔들림이 크다.
- 대안을 합성 입력에서만 비교했다. τ = 2 × q0.999로 진폭에 여유를 두면 정상 10장의 점수가 모두 0이었고, 반지름 3 / 6 / 11 px 원형 이물의 점수는 145 / 572 / 1830이었다.
- 최소 넓이 25 px는 5 × 5 px에 해당하는 설계값이다. mm로는 미측정이다.
- 실제 사진으로 고른 값이 아니다. 실제 사진에서 이 규칙이 맞지 않으면 그대로 보고하고 새 버전으로 고친다.

- **채널 선택 근거:** RGB 최댓값은 색 변화와 밝기 변화를 모두 잡는 일반 규칙이다. 다만 이물이 분홍색이라는 것을 본 뒤에 고정했다(§0).
- **계수 2, q0.999, 최소 넓이 25 px:** 정상 calibration이 조명당 1장뿐이라 통계적 근거가 약하다. 사전에 고정한 설계값이다.
- **위치 확인 (사후, 평가 전용):** 방법을 고정한 뒤 F0 반복 1에서 이물 중심을 anchor 좌표로 한 번 표시한다. NG 덩어리의 중심이 그 표시에서 30 px 안이면 "위치 일치"로 기록한다. 판정에는 쓰지 않는다.
- 라벨은 `surface_foreign_object_simulation`이다. 전기적 고장·단선 라벨은 없다.

## 6. Cycle과 C0–C3 규칙 (고정)

**Cycle 목록** (모든 최초 cycle이 분모다)

| cycle | 첫 촬영 | 대체 조명 촬영 | 라벨 | 수 |
| --- | --- | --- | --- | --- |
| normal | L0 반복 3 | L1 반복 3 | 정상 (전기적 상태 미확인) | 1 |
| foreign | F0 반복 k | F1 반복 k | 모사 이물 | 3 |
| lowlight | L2 반복 k | L1 반복 k | 정상, 입력 스트레스 | 3 |
| blur | 초점 흐림 k | 없음 | 정상, 입력 스트레스 | 3 |
| background | 흰 배경 k | 없음 | 정상, 입력 스트레스 | 3 |
| tilt | 기울임 k | 없음 | 정상, 입력 스트레스 | 3 |

- lowlight의 k = 1, 2는 대체 촬영이 참조·calibration 사진이라 검사 결과가 자명하다. 표에 그렇게 표시한다.
- 대체 촬영이 없는 cycle에서 재촬영이 요청되면 `retake_unavailable`로 기록하고 REVIEW로 끝낸다.

**조건별 규칙**

- **C0:** 첫 촬영을 품질 정책 없이 L0 참조로 검사한다. 정렬이 실패하면 ERROR다.
- **C1:** 첫 촬영의 계산용 영상을 ×0.25로 줄였다가(MATLAB 호환 bicubic) ×4로 되돌린 뒤 같은 검사를 한다. 되돌리는 방법은 SwinIR-S ×4(기존 checkpoint, tile 64)와 대조용 Bicubic 두 가지다.
  - 참조와 calibration 사진도 같은 처리를 거친다(matched).
  - 정렬 homography는 원본에서 구한 것을 그대로 쓴다.
  - 이것은 실물 사진에 ×4 왕복을 가한 새 family(`phone_x4_roundtrip`)다. 기존 benchmark의 ×4 조건과 합치지 않는다. 조명이 다른 사진을 SR 정답으로 쓰지 않으며 PSNR/SSIM은 계산하지 않는다.
- **C2:** 첫 촬영에 품질 정책을 적용한다.
  - PASS면 L0 참조로 검사한다(촬영 1장).
  - PASS가 아니면 대체 조명 촬영을 1회 요청한다. 그 사진이 PASS면 L1 참조로 검사한다(촬영 2장). PASS가 아니면 REVIEW로 끝낸다(촬영 2장, 미해결).
  - 정책은 v0.1(같은 ROI 적용)과 v0.2 두 가지를 따로 실행한다.
- **C3:** L0와 L1 두 장을 항상 찍는다. 각각 자기 조명의 참조로 검사하고, 하나라도 NG면 NG, 둘 다 OK면 OK다. 대체 촬영이 없는 cycle은 NA다.

**보고 지표**

- cycle별 최종 상태(OK/NG/REVIEW/ERROR/NA), 촬영 수, 해결 여부.
- 모사 이물 cycle 중 최종 OK 수(놓침), 정상 cycle 중 최종 NG 수와 NG·REVIEW 수. 모두 분모와 함께 쓴다.
- 이물은 1종 1위치의 반복 3회, held-out 정상은 1 cycle이다. 비율이 아니라 건수로 쓰고, 일반 결함 검출 성능으로 쓰지 않는다.
- 소프트웨어 처리 시간만 기록한다. 실제 촬영 시간과 장비 처리량은 미측정이다.
