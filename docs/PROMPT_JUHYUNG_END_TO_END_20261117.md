# 주형의 최종 목표 달성을 위한 통합 실행 프롬프트

2026-11-17 사용자 지시. 지혁의 완료 bank-domain 자료를 주형이 받아 통합하고 실제로 남은 작업을 이어간다. 현재 Claude 환경에서 설계 판단, 남은 구현, 실행, 사진 결과, 검토와 수정, 보고서·포스터 반환까지 맡는다. 기존 Fable 5.2 환경을 이어가고 실제 사용 모델을 실행 기록에 남긴다.

## 최종 목적과 완료할 결과

실제 촬영에서 저조도·흐림·해상도 저하가 생겼을 때 작은 결함을 보존하면서 검사하는 방법을 만들고, 복원이 도움이 되는 조건과 결함을 지우거나 변형하는 조건을 같은 사진과 수치로 확인한다. 그 근거에 따라 직접 검사·복원 후 검사·대체 촬영·보류를 선택할 수 있게 한다.

반드시 완성할 산출물은 다음과 같다.

- 같은 결함 위치의 원본, 열화 입력, Bicubic, SwinIR RGB 확대 비교. 대응 GT와 검사 지도를 포함한다.
- 개선·억제·형상 변화·변화가 작은 사례의 근거와 실패 사례. 기존 사례 선정 기준과 사후 분석 여부를 적는다.
- 실제 기판의 정상·모사 이물·저조도·흐림·대체 조명 사진 결과.
- 동일 query에서 normal bank만 바꾼 비교와 실제 PatchCore 기본24+확장4 결과.
- 복원·재촬영·보류의 동작과 판정 근거를 볼 수 있는 실행 가능한 결과 화면.
- 그림과 수치가 연결된 최종 보고서, 편집 가능한 공식 A0 PPTX와 PDF, 재현 기록, 실제 private 결정 노트.

UNO·실시간 시연은 준비된 범위에서 연결한다. 먼저 위 사진·소프트웨어 결과를 마친다. 새로운 ANN, 자동 drift 보정, 조명 피드백 보드, XY scanner는 핵심 결과에 필요한지 판단한 뒤 별도 채택한다.

## 2. 부족한 연결을 설계하고 구현한다

최종 목적에 대해 구현됨, 저장 결과로 만들 수 있음, 새 실행 필요, 사람 입력 필요를 각각 실제 파일과 연결한다. 이 판단은 기존 PROGRESS와 설계 문서에 짧게 기록한 뒤 구현을 계속한다.

정렬용 축소 이미지와 검사용 원해상도 ROI의 좌표 관계, 타일·배율, 품질 정책, 기준 사진 검사와 PatchCore 경로, 복원 후 검사, 대체 입력, 최종 REVIEW를 한 흐름으로 점검한다. 작은 결함이 전처리에서 사라지는 경우를 확인한다. 확대 그림에서 생긴 보기 좋은 질감을 결함 보존으로 판정하지 않는다.

SwinIR x4가 저조도나 실제 흐림을 복원할 수 있다고 가정하지 않는다. 해당 열화와 모델의 적용 범위를 먼저 대조하고, 직접 검사·복원·재촬영의 결과를 관측한다. 필요한 작은 연결 기능은 기존 코드를 재사용해 구현하고 영향을 받는 진입점과 회귀검사를 확인한다.

새 threshold나 선택 정책이 필요하면 normal train/calibration 또는 분리된 development 근거로 고정한다. test GT나 새 평가 결과로 유리한 방법을 고르지 않는다. 선택 정책이 검증되지 않은 경우에는 실제 동작하는 기본 정책과 미검증 후보의 상태를 명확히 기록한다. 개선 실패도 실제 수치와 사진으로 반환한다.

## 3. 새 촬영을 기다리지 않고 첫 사진 결과를 만든다

기존 선정 사례와 원본 RGB·GT·저장 map·복원 캐시를 먼저 찾는다. RGB가 없다면 고정된 소수 사례만 동일 checkpoint·열화 조건으로 처리해 저장한다. 전체 과거 실험을 반복할 필요는 없다.

같은 공간 범위에서 원본/열화/Bicubic/SwinIR RGB를 나란히 놓고, 대응 GT와 검사 지도를 붙인다. image ID, crop 좌표, 원해상도, 출력 크기, 실제 확대 배율, 열화 조건, source/checkpoint를 그림 인덱스에 넣는다. 검사 지도는 동일 사례 안에서 같은 색 범위로 표시한다.

개선·억제·형상 변화·변화가 작은 사례를 기존 기준으로 포함한다. 해당 사례가 없으면 없다고 적는다. 사후 선택과 시각화 crop은 사후 분석으로 표시한다. 그 선정 사례로 일반 성능을 추정하지 않는다.

실제 스마트폰 사진의 작은 소자·모사 이물을 확대하고, 촬영 원본·인위적 x4 입력·복원 결과·차이 검사 경로를 표시한다. 고해상도 PNG와 실제 열리는 HTML 갤러리, 조건별 인덱스를 먼저 반환하고 다음 단위를 이어간다.

## 5. 필요한 촬영을 구체적으로 요청하고 독립 작업을 계속한다

동봉된 docs/PHOTO_CAPTURE_REQUEST_20261117.md와 capture_plan_50.csv는 촬영 전 제안이다. 기존32장 계획의 빈틈은 저조도·흐림에 결함이 없는 정상 기판만 사용한다는 점이다. 최종 목표를 위해 작은 모사 이물을 둔 채 선명·저조도·흐림을 비교하는 보조18장을 추가했다.

실제 보유 사진으로 이 조합을 이미 만족하는지 먼저 확인한다. 같은 위치·이물·카메라 자세·기록을 확인할 수 있는 기존 development 사진은 활용한다. 새 평가 세션을 기존 사진으로 대체하지 않는다. 촬영 계획은 실제 촬영 전에 고정하고 수행되지 않은 행은 계획으로 남긴다.

기본32장은 v2로 기록하고 정상 흐림 두 cycle 중 하나의 L1도 흐리게 해서 같은 조명 참조의 L1흐림 문제를 확인한다. 보조18장은 작은 모사 이물3위치 × 선명/저조도/흐림 × 최초/대체 사진이다. 기본 평가14cycle과 보조challenge9cycle을 각각 보고한다. 같은 기판·같은 이물의 반복 사진은 독립 결함 개수로 세지 않는다.

capture_plan_50.csv는 촬영 기록용 초안이다. 기존 plan_from_sheet와의 추가 열·cycle 호환성을 확인하고 필요한 변환은 주형이 연결한다. 기록표만 존재하는 상태를 실행 성공으로 처리하지 않는다.

사람 판독은 알고리즘 결과를 보여주기 전에 받는다. 실제 취득시간을 기록하고, 선명한 실제 촬영본은 photometric GT의 조건을 만족하는지 확인한다. 조명·노출이 다른 독립 촬영끼리는 PSNR/SSIM을 무조건 계산하지 않는다. 모사 이물 위치 표시는 실제 제작 결함의 pixel GT와 구분한다.

실제 미세 결함 기판과 정밀 GT가 없으면 benchmark의 GT 있는 사례에서 결함 보존을 평가하고 실물에서는 모사 표면 이물의 관찰 가능성과 동작 범위를 보고한다. 필요한 사람 입력과 촬영 요청은 한 번에 정리해 보내고, 나머지 구현·그림·분석·보고서를 계속한다.

## 6. 전체 검토를 수행하고 실제로 고친다

사진과 숫자를 같은 image/cycle/condition ID로 연결한다. 정상의 OK/NG/REVIEW, 결함의 OK/NG/REVIEW를 모두 보고하고 미확인 label은 그대로 둔다. NA와 재사용, 실제 capture와 offline replay를 표시한다.

보고서의pooled/평균AU-PRO 혼용, family별seed, 원근중심보정/화면이동 구분,147/423초의source·조건수·전원혼재를 고친다. HTMLv0.2banner는 저장 결과render 또는사본문구수정으로 정정한다. 팀번호·저자·교수·소속·제목은 확인된 값으로 넣는다. 미확정이면 최종 반환 첫부분에 담당자가 채울 항목을 적는다.

변경 기능의 정상 진입점·기존caller·실패 경로·저장/재개를 확인하고 관련 테스트와 CPU smoke를 실행한다. source가 같은 기존 테스트는 재사용한다. 보고서 링크, 이미지, 표·숫자, HTML 실제 화면, PPTX/PDF의A0 1쪽과 확대 가독성을 직접 확인한다.

가능한 경우 별도 검토 세션에 실제 diff·사진·표를 주어 검토받고 수정한다. 사용한 모델과 검토 범위를 남긴다. 같은 모델의 자체 검토도 그렇게 기록한다. 검토 의견 목록에서 멈추지 않고 실제 수정본을 만든다.

## 7. 반환과 완료 기준

공개 Git에는 코드와 허용된 scalar metadata를 반환한다. 사진·GT·map·bank·weights·dataset·사진 포함HTML/PPTX/PDF·실제private노트는 비공개 파일로 직접 반환한다.

최종 비공개 묶음에는 다음을 넣는다.

- 실행 가능한 사진 결과HTML과 고해상도 비교PNG, image/crop/조건 인덱스.
- 실제 bank24+4 결과와 누락·실패 조건, 필요한 consumer 입력5파일.
- 실제 촬영 결과·원본/대체 관계·사람 판독·측정시간과 누락 항목.
- 최종 보고서, 공식A0 PPTX/PDF와 포스터에 실제 삽입한 그림.
