# 새 평가 촬영 세션 계획 v1 (2026-11-15 고정, 촬영 전)

- **목적:** 2026-11-15 development 세션을 본 뒤 정한 방법(품질 정책 v0.3, golden-reference v0.1)을, 방법을 정할 때 보지 않은 새 사진으로 한 번 평가한다.
- **고정된 것:** 방법, 임계값, 아래 촬영 목록, 분석 순서. 새 사진을 본 뒤에는 바꾸지 않는다. 바꿔야 하면 새 버전으로 남기고 이 세션의 결과는 그대로 보고한다.
- **준비물:** 같은 그래픽카드, 같은 스마트폰, 책상 조명, 같은 분홍색 조각, 종이 테이프(또는 포스트잇), 스톱워치(다른 폰). 추가 구매는 없다.

## 1. 고정할 것

1. 폰을 책으로 고정한다. 구도는 지난 세션의 L0 사진과 같게 한다(브래킷 왼쪽, 금색 접점 위쪽, 기판이 화면 가운데).
2. 기판 네 모서리 위치를 테이프로 표시한다.
3. **조명 위치 두 곳을 테이프로 표시한다.** L0(기준)와 L1(왼쪽 낮은 측면)이다. 조명을 옮길 때마다 표시에 맞춘다. 지난 세션에서는 L0를 매번 다시 만들어 반복 간 차이가 컸다.
4. 방 조명 상태를 한 가지로 정하고 세션이 끝날 때까지 바꾸지 않는다.
5. 카메라는 일반 사진 모드, 1× 렌즈, 플래시 꺼짐, JPEG이다. AE/AF 잠금과 HDR의 실제 상태를 기록표에 적는다.

## 2. 촬영 목록 (32장)

| 묶음 | 내용 | 사진 |
| --- | --- | --- |
| A. 참조 | 이물 없음. L0 1장, L1 1장 | 2 |
| B. 정상 보정 | 이물 없음. L0 1장, L1 1장. 참조와 따로 찍는다 | 2 |
| C. 정상 평가 | 이물 없음. cycle 4개, cycle마다 L0 1장 + L1 1장 | 8 |
| D. 모사 이물 | 같은 분홍 조각을 세 위치(P1, P2, P3)에 놓는다. 위치마다 cycle 2개, cycle마다 L0 1장 + L1 1장 | 12 |
| E. 저조도 첫 입력 | 이물 없음. cycle 2개. 첫 사진은 방 조명을 끈 상태, 대체 사진은 L1 | 4 |
| F. 흐린 첫 입력 | 이물 없음. cycle 2개. 첫 사진은 L0에서 수동 초점을 벗어나게, 대체 사진은 초점을 다시 맞춘 L1 | 4 |

- **이물 위치:** P1은 지난 세션과 같은 기판 가운데, P2는 왼쪽 작은 소자 밀집 영역의 빈 초록 면, P3는 오른쪽 메모리 칩 사이의 빈 초록 면이다. 접점과 커넥터 안에는 놓지 않는다.
- **cycle 안에서는** 기판과 이물을 건드리지 않고 조명만 옮긴다.
- **cycle 사이에는** 조명을 표시 위치로 다시 맞춘다. D 묶음에서 같은 위치의 두 번째 cycle은 이물을 들어냈다가 같은 자리에 다시 놓는다.
- 모든 사진은 한 번씩만 쓴다. 참조·보정 사진을 평가나 대체 사진으로 다시 쓰지 않는다.
- 사진이 흔들렸으면 지우지 말고 같은 칸을 다시 찍어 `attempt=2`로 적는다.

## 3. 시간 기록

cycle마다 "조명을 맞추기 시작한 때"부터 "마지막 사진의 셔터가 끝난 때"까지를 스톱워치로 재서 기록표의 `capture_seconds`에 초 단위로 적는다(첫 사진 행에만). 재지 못한 cycle은 비워 둔다. 비운 칸은 미측정으로 보고한다.

## 4. 기록표

`docs/phone_eval_capture_sheet_template.csv`를 사진 폴더에 `capture_sheet.csv`로 복사해 채운다. 32행이 미리 들어 있고, `file` 열에 실제 파일 이름만 넣으면 된다. `station_role`, `cycle_id`, `light` 열에서 실행 계획이 자동으로 만들어진다.

## 5. 사람 판독표

`docs/phone_human_legibility_template.csv`를 쓴다.

- 판독자는 **알고리즘 결과와 report.html을 보기 전에** 원본 사진만 보고 채운다.
- 사진마다 관찰 영역(기판의 초록색 면) 안의 소자·납땜·인쇄를 읽을 수 있는지를 `well_visible` / `hard_to_read` / `uncertain` 중 하나로 적는다.
- 판독자 이름(또는 이니셜)과 기록한 시각을 적는다.
- 분석 도구나 AI의 사진 해석으로 이 표를 채우지 않는다.

## 6. 분석 (고정)

1. 기록표로 실행 계획을 만들고, 참조·보정·평가 목록이 위 표와 맞는지 확인한다. 그 뒤에 비교를 실행한다.
2. 실행 명령: `run_phone_station_compare.py --input <폴더> --recipe <recipe.json> --output <새 폴더> --kind real --assets-root <checkout> --device cuda`
3. 임계값은 이 세션의 참조·정상 보정 사진으로만 정한다(golden-reference의 τ). 이물 사진의 결과로 다시 고르지 않는다.
4. 보고: 모든 최초 cycle 14개가 분모다.
   - C0와 C3를 먼저, 이어서 C2 v0.3 / v0.2 / v0.1, C1 Bicubic / SwinIR.
   - 정상 cycle(C, E, F 묶음 8개) 중 최종 NG 수, 모사 이물 cycle 6개 중 최종 NG 수와 위치별 수, REVIEW 수, 사진 수, `capture_seconds`.
   - 이물 위치 표시는 방법 실행 뒤에 위치별로 한 번 하고, 위치 일치 확인에만 쓴다.
5. 사람 판독표가 있으면 정책별로 `hard_to_read` 사진의 PASS 수, `well_visible` 사진의 REVIEW/RETAKE 수, 미해결 cycle 수를 같은 분모에서 센다. 없으면 NA다.

## 7. 이 평가로도 말할 수 없는 것

- 보드 1개, 이물 1종이다. 공장의 오탐률·미검률·처리량은 추정하지 않는다.
- 전기적 정상 여부는 확인하지 않는다.
- mm 분해능과 lux는 측정하지 않는다.
