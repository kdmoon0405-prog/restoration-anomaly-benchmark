# 개선 설계 v0.4 후보 — 열화 입력에서 작은 결함을 확인하는 검사 경로 (2026-11-19)

작성: Claude Opus 5.5 (`claude-opus-5-5`). Fable 5.2 검토 전이다. **[구현]** = 이번에 코드가 있는 것, **[개발 확인]** = 같은 세션으로만 확인한 것, **[제안]** = 아직 코드·근거가 없는 것.

## 1. 목표와 판단 근거

- 목표: 어둡거나 흐린 실물 사진에서 작은 결함(모사 이물)을 놓치지 않는다. 복원·재촬영·사람 검토 중 무엇으로 넘길지를 근거와 함께 정한다.
- 근거 1 (새 촬영 50장): 작은 이물은 저조도·흐림 사진에서도 **눈으로 보였다.** 판정을 막은 것은 **정렬**이었다. 조명이 바뀐 사진이 L0 기준에 맞지 않았다.
- 근거 2 (벤치마크): ×4 복원은 화질 지표를 올려도 결함 대비를 낮출 수 있다(Hazelnut 70장 중 30장 영상별 저하, 노이즈 σ15에서 SwinIR < Bicubic).
  - 정상 bank를 검사 입력과 같은 처리로 맞추면 Screw 판정이 크게 오른다(seed 11, 0.67 → 0.92).
  - 처리가 어긋나면 화질이 좋아도 낮다(0.73).
- 근거 3 (실물 ×4 왕복): 복원은 물체 대비를 낮췄다(차이/τ 5.4–6.7 → SwinIR 3.5–4.4). 대신 다른 곳의 작은 차이를 지워, 가장 큰 덩어리가 물체에 놓이는 경우가 늘었다(개발).

## 2. 대안 비교

| 안 | 내용 | 비용 | 이번 근거 | 선택 |
| --- | --- | --- | --- | --- |
| A. 현행 v0.3 유지 | L0 anchor 정렬, 같은 조명 참조로 품질 판정 | 0 | L1 25/25 정렬 실패, 대체 조명 무효 | 기각 |
| B. 정렬 전 대비 균등화(CLAHE) | 밝기 차이를 줄인 뒤 같은 anchor에 정렬 | 작음 | 16 → 13 성공(악화) | 기각 |
| **C. 같은 조명 참조 정렬** | 각 사진을 기대 조명의 참조에 정렬·비교, 참조끼리는 같은 자세 가정 | 작음(래퍼) | 16 → 41 성공, 대체 조명 경로 동작 | **선택 (v0.4 후보)** |
| D. 학습형 특징(SIFT/딥 매칭) | 조명 강인 특징 | 중간(의존성) | 없음 | 보류 |
| E. 복원을 운영 경로에 넣기 | 저조도·흐림 사진을 SwinIR로 복원 후 검사 | 큼 | SwinIR ×4는 저조도·흐림용이 아님, 대비를 낮춤 | 기각(연구 비교군 C1로만 유지) |

## 3. 입력·출력 계약

- **입력:**
  - 사진 폴더 + `capture_sheet.csv` (v2 열: `station_role`, `cycle_id`, `light`, `capture_group`, `case_id`, `planned_condition`)
  - recipe (anchor, ROI, 자세 허용 범위)
- **참조 사진 규칙:** 조명마다 참조 1장과 정상 보정 1장이 있어야 한다. 참조·보정 사진은 재사용하지 않는다(실행기가 거부, 구현).
- **[제안] 블록 정상 사진:** 카메라나 기판을 다시 놓은 블록(예: 작은 이물 블록)마다 조명별 정상 사진 1장을 둔다.
- **출력** (구현):
  - cycle별 OK / NG / REVIEW / ERROR와 이유, 사용 사진 수
  - 묶음별 집계 `summary_by_group.csv`
  - 결과 화면 `report.html`, 이력 `station_events.jsonl`
- **[제안] 덩어리 목록:** NG면 상위 3개 덩어리의 위치·면적을 남긴다(F3).

## 4. 검사 흐름

1. 입력 확인: 기록표, 파일, SHA-256, 중복, 묶음 혼합 거부 **[구현]**.
2. 정렬: 사진의 기대 조명 참조에 ORB+RANSAC로 정렬한다(inlier ≥ 30, 비율 ≥ 0.25, 재투영 오차 중앙값 ≤ 1.5 px) **[개발 확인: C]**. 정렬 실패는 RETAKE다.
3. 품질 v0.3: 같은 조명 참조와 비교한다. 새 포화·암부 > 1 %, 선명도 비 < 0.5, 어두움이면 RETAKE / REVIEW **[구현]**.
4. 검사: 같은 조명 참조와의 국소 정규화 차이다. τ = 2 × (정상 보정 사진 차이의 q0.999), 덩어리 ≥ 25 px면 NG **[구현]**.
5. 첫 사진이 PASS가 아니면 대체 조명 L1을 1회 촬영하고 2–4를 반복한다 **[구현]**. L1도 PASS가 아니면 REVIEW다.
6. REVIEW 처리 **[제안]**:
   - 사람에게 원본·L1 사진과 덩어리 위치를 함께 보여 준다. 사람 판정(OK / NG / 재촬영)과 시간을 기록한다.
   - 사람 판정 전에는 출하하지 않는다(REVIEW ≠ OK).

## 5. 복원을 쓰는 조건

- **운영 경로에서는 쓰지 않는다.** 실물 저조도·흐림은 대체 조명과 재촬영으로 해결한다.
- **저해상도 카메라 입력**(벤치마크의 ×4 상황)에서만 후보로 둔다. 그때는 정상 bank를 같은 처리(같은 복원기)를 거친 정상 영상으로 만든다.
  - 임계값은 같은 처리의 정상 보정 영상으로 정한다.
  - bank와 입력 처리가 다르면 쓰지 않는다(Bicubic bank + SwinIR 입력 0.73).
- 화질 지표(PSNR/SSIM)로 복원기를 고르지 않는다. 검출 지표와 영상별 회귀 수를 함께 본다.

## 6. 임계값·bank 보정

- 임계값은 정상 보정 사진(또는 정상 calibration split)으로만 정한다. 시험 GT·라벨은 평가와 사후 설명에만 쓴다.
- 조명마다 따로 보정한다. 조명당 보정 사진이 1장뿐이라 τ의 통계 근거가 약하다. **[제안]** 다음 세션에서 조명당 정상 보정 3장을 쓰고, q0.999를 묶어서 추정한다.

## 7. 실패 시 동작 (구현)

| 상황 | 동작 |
| --- | --- |
| 정렬 실패 | 해당 사진 RETAKE. 대체가 없으면 REVIEW |
| 파일 누락·읽기 실패 | RETAKE(이유 기록) |
| recipe / 계획 오류, 출력 폴더 존재 | 아무것도 쓰지 않고 종료 코드 2 |
| 메모리 예산 초과 | BLOCKED_MEMORY 기록 |

## 8. 산출물 방법

- 같은 위치 확대는 `make_phone_eval_cases.py`로 만든다. 사후 위치 표시에서 원본 해상도·검사 해상도·×0.25·Bicubic·SwinIR·차이 지도를 같은 좌표로 보여 준다.
- 벤치마크 사례는 기존 분류 규칙으로 사후 선정한다. 분모와 선정 기준을 함께 쓴다.

## 9. 완료 기준

1. 다음 촬영 세션(계획 v3 제안: v2 + 블록 정상 사진, 조명당 보정 3장)에서 v0.4 후보를 **고정 방법**으로 평가한다.
   - 기본 묶음: 정상 OK 비율, 이물 NG(위치 일치) 비율, REVIEW 수, 사진 사용 수를 v0.3과 같은 표로 보고한다.
   - 작은 이물 묶음: 물체 위치 NG 비율.
2. 사람 판독표로 품질 판정의 과잉·과소 거부를 계산한다.
3. 실제 cycle 촬영 시간을 기록한다.
